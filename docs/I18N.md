# Fika Internationalization (typesafe-i18n)

Fika uses [`@lofcz/typesafe-i18n`](https://github.com/lofcz/typesafe-i18n) `5.27.4` (TypeScript 6–compatible fork of [typesafe-i18n](https://github.com/ivanhofer/typesafe-i18n)), aliased as `typesafe-i18n` in `package.json` — the same setup as [sciobot-next](https://github.com/sciobot/sciobot-next). Import paths and CLI commands stay `typesafe-i18n`.

## Why `baseLocale: en`?

Sciobot-next uses `cs` as its base locale because Czech is the primary product language. Fika is being **migrated from Chinese UI strings** to en/cs/sk/pl. During mass migration, **English is the canonical source for keys** — translator agents write English first, then cs/sk/pl counterparts. This matches the migration direction (Chinese → English → CEE languages) and keeps key naming stable for the 50 parallel agent batches.

Shared locale union with sciobot: `cs | en | sk | pl`.

## Locales and namespaces

| Locale | Folder |
|--------|--------|
| en (base) | `src/i18n/en/` |
| cs | `src/i18n/cs/` |
| sk | `src/i18n/sk/` |
| pl | `src/i18n/pl/` |

Namespaces (each has `index.ts`):

| Namespace | Purpose |
|-----------|---------|
| `common` | Shared buttons, errors, loading |
| `editor` | Editor chrome, panels, toolbars |
| `canvas` | Canvas operations, alignment, link dialog |
| `screen` | Presentation mode |
| `mobile` | Mobile UI |
| `export` | Export dialogs |
| `configs` | User-visible labels from configs (hotkeys, animations, charts, shapes, …) |
| `components` | Shared component strings |

Each locale folder has a root `index.ts` (empty `{}`) that re-exports nothing manually — typesafe-i18n discovers namespace subfolders automatically.

## Commands

```bash
bun run i18n          # watch mode during development
bun run i18n:build    # one-shot codegen (run after adding keys)
```

## Generated files — do not edit

- `src/i18n/i18n-util.ts`
- `src/i18n/i18n-util.async.ts`
- `src/i18n/i18n-util.sync.ts`
Listed in `.prettierignore`.

## React usage

```tsx
import { useI18nContext } from '@/i18n/useI18nContext'

function SaveButton() {
  const { LL } = useI18nContext()
  return <button>{LL.common.save()}</button>
}
```

Pattern: `const { LL } = useI18nContext()` then `LL.<namespace>.<key>()`.

Wrap the tree with `TypesafeI18n` from `src/i18n/i18n-react.ts`.

## Plain TypeScript files (hooks, configs, stores)

```typescript
import { getLL } from '@/i18n/getLL'

const LL = getLL()
message.success(LL.common.save())
```

`getLL()` uses synchronous loading via `i18n-util.sync` — suitable for module-level config arrays and non-component code.

## Locale detection and host sync

`src/i18n/locale.ts`:

| Source | Priority |
|--------|----------|
| `?locale=cs` URL param | 1 |
| `window.__FIKA_LOCALE__` | 2 |
| Default `en` | fallback |

```typescript
import { getFikaLocale, setFikaLocale } from '@/i18n/locale'
import type { Locales } from '@/i18n/locale'
```

### sciobot-next (React host) integration

When Fika is embedded in sciobot-next:

1. **Mount prop / global before boot:** set `window.__FIKA_LOCALE__ = 'cs'` before the Fika bundle loads.
2. **URL param:** load iframe/src with `?locale=cs`.
3. **postMessage (future):** host sends `{ type: 'fika:setLocale', locale: 'sk' }`; Fika listener calls `setFikaLocale`, reloads namespaces via `loadNamespaceAsync`, then `setLocale` from `useI18nContext()`.

Shared locale union: `cs | en | sk | pl` — same as sciobot-next `Locales` type.

## Adapter

Fika uses the typesafe-i18n React adapter (`<TypesafeI18n locale={locale}>`), same as sciobot-next. Translation files live at `src/i18n/<locale>/<namespace>/index.ts`.

## Czech plurals

When adding pluralized strings, Czech requires **6 plural forms** in typesafe-i18n syntax:

```
{count} {{zero|one|two|few|many|other}}
```

See [typesafe-i18n pluralization docs](https://github.com/ivanhofer/typesafe-i18n#plural-rules).
